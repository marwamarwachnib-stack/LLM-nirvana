# Experiment 1 — Python bug detection with CodeBERT on BugInPy

> Final report generated by Phase 10 of `BugInPy_CodeBERT_Experiment.ipynb` on Google Colab (T4 GPU), from the researcher's run.

**Run ID:** 20261112_122126 · **Dataset:** BugInPy commit 11c5f1eea954a42132cfd06bf257766a7963e0fd · **Model:** microsoft/codebert-base

## Data
* 501 BugInPy bugs → 473 usable bugs, 17 projects; function-level samples (Option C labelling, length-matched easy negatives).
* After normalisation and de-duplication: **1799 samples** (772 buggy / 1027 clean).
* Protocol: grouped 5-fold **cross-project** cross-validation, validation on held-out projects, no project / bug / duplicate leakage (split SHA-256 `794ae76723369776072873e8c68bca84df90c7edfcc8801453c930e076fa56f4`).

## Diagnostics (Phase 8)
* **8.7** initial run: training loss stayed at ≈ 0.69 (median drop 2%), predictions collapsed around 0.5 → verdict A (no learning).
* **8.8** sanity check: 64 training samples memorised (final loss 0.0074, accuracy 1.000) → pipeline can learn.
* **8.9** extended run (≤ 15 epochs, lr ∈ {2e-5, 5e-5} chosen per fold on validation): in the 5 runs where the training loss fell ≥ 10%, validation loss rose and test AUC stayed at chance (median 0.512); best fit fold 2: train AUC 0.972 → test AUC 0.522 → learning without transfer.
* **8.10** positive control (injected `_ = 1 / 0`, fold 1, unseen projects): ROC-AUC 1.000, F1 1.000 (reproduced twice).

## Key findings
1. **No model detects real bugs better than chance** across projects: every 95% CI contains 0.5. CodeBERT does not differ significantly from the best lexical baseline (TF-IDF + RF).
2. **The pipeline is correct:** it memorises training data (sanity check: final loss 0.0074) and detects injected obvious bugs in unseen projects (ROC-AUC 1.000).
3. **Learning without transfer:** with a longer budget CodeBERT fits its training projects while the validation loss rises (8.9).
4. **No subgroup or project explains the failure** (Phase 10.3 / 10.5): performance stays near chance for short and long functions, small and large fixes.
5. Threshold metrics are dominated by the class ratio: the trivial "always buggy" classifier has a higher F1 than every model; ROC-AUC and average precision are the informative metrics.

## Interpretation
Under a strict, leakage-free, cross-project protocol, fine-tuned CodeBERT cannot distinguish real buggy Python functions from fixed or unrelated functions using the function text alone, although the same pipeline easily detects syntactically obvious injected bugs. Real bugs are semantic and context-dependent.

## Limitations
Single function without context; 512-token window; 1,799 samples; single seed; one model (CodeBERT); cross-project setting only.

## Next steps
Within-project split; additional information (static analysers, dynamic execution e.g. Pynguin-generated tests, wider context); task reformulations closer to debugging practice (fault localisation with a failing test, patch correctness); larger code models / LLMs.
