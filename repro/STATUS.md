### 0.1 Bottom line

**The current work is a test-generation reproduction. It does not yet perform any fault localization.**
No SFL code, no per-test spectra, no injected or real faults, and no localization metric exist in `repro/`
(full-text search of `repro/scripts`, `repro/env` for ochiai/tarantula/dstar/suspicious/spectrum/fault/mutant: no match;
saved coverage JSON files contain no per-test `contexts`, e.g.
`runs/qwen3-4b-instruct/basic/small_cat2/affine-cipher/iter_1/suite_stmt_coverage.json`).
What exists is the foundation SFL needs: pinned environments, validated test-execution sandboxes,
per-test pass/fail outcomes, and LLM-generated suites. Section 0.6 gives the smallest step to add SFL.

### 0.6 Problems and limitations

1. **No SFL** (see 0.1). Coverage is aggregated per suite; per-test spectra are not recorded.
2. **No faults with known locations.** The small set and p2 are correct programs; there is no ground truth for localization.
3. **Throughput**: ~8–14 min per LLM call on 4 CPU cores; the planned queue (≈ 95 modules, up to 5 calls for 13 of them) needs on the order of a day of CPU time.
4. **Model behaviour**: the 4B model pasted the module into its tests in 2/2 replies; scores depend on the logged repair (`scripts/extract.py: remove_redefinitions`).
5. **Oracle quality**: 33/63 LLM tests fail on the *correct* programs. Used as-is in SFL they would create false failing spectra; they must be filtered (0.7).
6. Correctness is measured per test, not per assertion as in the paper (README, deviations).
7. Container restarts stop the queue (0.3).

### 0.7 Smallest rigorous next step to add SFL (proposal — not implemented)

Re-uses everything already produced; **no LLM calls, no restart of the queue**.

1. **Faults with ground truth**: first-order mutants of the 39 small-set reference programs (`example.py`), generated by
   MutPy (already installed with Pynguin, 20 standard operators). The mutated line is the fault location. Keep mutants that
   at least one suite detects; sample ≤ 10 per program, fixed seed.
2. **Suites compared on the same mutants**: (a) Exercism developer tests (baseline), (b) saved Pynguin tests,
   (c) LLM tests from `runs/` (only tests that pass on the correct program, so failures mean fault detection, not bad oracles),
   (d) developer + LLM.
3. **Per-test spectra**: coverage.py `dynamic_context = test_function` + junit outcomes.
   Feasibility checked 21:33 UTC on affine-cipher with the developer tests: 16 tests, 31 lines with per-test contexts recorded,
   line 26 executed by 8 tests (`/opt/repro/work/sfl_feasibility`, scratch, no result claimed).
4. **Scores and metrics**: Ochiai (primary), Tarantula, DStar (*=2); statement ranking with best/worst/average tie handling;
   Top-1/3/5, EXAM, MRR; detection rate per suite; paired Wilcoxon + Vargha–Delaney Â between suites over mutants.
5. Files: new `scripts/sfl/` and `results/sfl/`; nothing existing changes.

Cost estimate: 39 programs × ≤ 10 mutants × 4 suites ≈ 1,560 pytest runs of 1–3 s ≈ 0.5–1.5 h CPU at low priority,
slowing the running LLM queue by a similar margin. LLM tests are only available for programs whose generation has finished,
so suite (c) grows with the queue. Implementation ≈ 300 lines.

Later steps toward the thesis (each needs a GPU to be practical; ~10 min per LLM call on this CPU):
LLM tests generated on the *buggy* version (scenarios S1/S3), LLM as test oracle, LLM-guided generation for diagnosability,
real faults (BugsInPy; Rezaalipour & Furia's FauxPy as reference implementation).
